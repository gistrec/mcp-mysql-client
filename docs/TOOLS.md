# Инструменты

Шесть инструментов. Пять читают, один пишет. Тип запроса определяет сервер, разбирая SQL, а не тот
инструмент, который выбрала модель: `DELETE` в `query` будет отклонён, `SELECT` в `execute` —
перенаправлен.

---

## `server_info`

Что за база на том конце и что с ней можно делать. Полезен первым вызовом в незнакомой установке и
при разборе отказов: права MySQL и разрешения MCP-сервера — два независимых ограничения.

**Параметры:** нет.

**Возвращает:** версию сервера, имя базы, пользователя, TLS, размер базы, вывод `SHOW GRANTS`
(или отметку, что он недоступен) и ограничения сервера — разрешённые операции записи, потолок
строк, таймаут, режим read-only транзакций.

---

## `list_tables`

Таблицы и представления подключённой базы.

**Параметры:** нет.

**Возвращает:** имя, тип, движок, кодировку, комментарий, размер данных и индексов в байтах,
оценку числа строк, время создания и последнего изменения.

> Оценка `rows_estimate` берётся из статистики InnoDB и расходится с реальностью — иногда в разы.
> Точное число даёт `SELECT COUNT(*)` через `query`.

---

## `describe_table`

Структура одной таблицы.

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `table` | string | — | Имя таблицы в подключённой базе |
| `include_indexes` | boolean | `true` | Включить индексы |
| `include_foreign_keys` | boolean | `true` | Включить внешние ключи в обе стороны |

**Возвращает:** столбцы (тип, обнуляемость, значение по умолчанию, ключ, комментарий), индексы
(сгруппированные, с порядком столбцов и длиной префикса), внешние ключи наружу и `referenced_by` —
ссылки на эту таблицу из других.

> `referenced_by` — то, что решает, безопасно ли удалять строки: именно эти ограничения дают
> `errno 1451` или каскадное удаление.

Несуществующая таблица — явная ошибка, а не пустой список столбцов.

## `query`

Читающий запрос: `SELECT`, `SHOW`, `DESCRIBE`, `WITH ... SELECT`.

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `sql` | string | — | Один запрос; несколько инструкций через `;` не выполняются |
| `params` | array | `[]` | Значения для `?` в порядке появления |
| `limit` | number | `MYSQL_MAX_ROWS` | Потолок строк для этого вызова; выше настройки не поднимает |

**Возвращает:** `rows`, `rowCount`, `truncated`, `columns` (имена и типы — единственное описание
пустого результата), `durationMs`.

> Если `truncated: true`, в ответе лежит **префикс**, а не весь результат. Уточните запрос или
> считайте агрегатами.

Запрос выполняется внутри `START TRANSACTION READ ONLY` (отключается `MYSQL_READ_ONLY_TX=false`).

---

## `explain`

План выполнения читающего запроса.

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `sql` | string | — | Запрос, план которого нужен |
| `params` | array | `[]` | Значения для `?` |
| `format` | `traditional` \| `json` \| `tree` | `traditional` | Формат плана |
| `analyze` | boolean | `false` | `EXPLAIN ANALYZE`: **выполняет** запрос и показывает фактическое время |

> `analyze: true` действительно запускает запрос — на большой таблице это стоит столько же,
> сколько сама выборка. `format` при этом игнорируется: `EXPLAIN ANALYZE` выбирает формат сам.

---

## `execute`

Изменяющий запрос: `INSERT`, `UPDATE`, `DELETE`, `REPLACE`. Помечен `destructive`.

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `sql` | string | — | Один изменяющий запрос |
| `params` | array | `[]` | Значения для `?` |
| `allow_full_table` | boolean | `false` | Подтверждение для `UPDATE`/`DELETE` без `WHERE` и `LIMIT` |

**Возвращает:** `affectedRows`, `changedRows` (для `UPDATE`), `insertId`, `warningCount`,
`durationMs`.

Что отклоняется:

- операция, для которой не включён `ALLOW_INSERT_OPERATION` / `ALLOW_UPDATE_OPERATION` /
  `ALLOW_DELETE_OPERATION`;
- `REPLACE` без прав и на вставку, и на удаление — он удаляет конфликтующую строку;
- любой DDL, при любых настройках;
- `UPDATE`/`DELETE` без `WHERE` и `LIMIT` без `allow_full_table: true`.

> Запрос выполняется сразу, без транзакции: откатить его отсюда нельзя. Перед `UPDATE` и `DELETE`
> стоит проверить выборку тем же условием через `query`.

---

## Общие ограничения

| Ограничение | Где задаётся |
| --- | --- |
| Одна инструкция на вызов | Всегда |
| Одна база данных | `MYSQL_DB`, сменить из диалога нельзя |
| Потолок строк | `MYSQL_MAX_ROWS`, по умолчанию 1000 |
| Таймаут запроса | `MYSQL_TIMEOUT_MS`, по умолчанию 30 с; по истечении соединение рвётся |
| Read-only транзакции для чтения | `MYSQL_READ_ONLY_TX`, по умолчанию включены |
| DDL | Недоступен всегда |
| `SET`, `USE`, `CALL`, `PREPARE`, `LOAD DATA`, `GRANT`, блокировки | Недоступны всегда |
| `SELECT ... INTO OUTFILE` | Недоступен всегда |
