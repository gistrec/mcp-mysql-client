# Разработка

## Требования

- Node.js 20+ (опубликованный пакет уже содержит собранный `dist/`, для `npx` ничего ставить не нужно).
- MySQL 5.7+ или MariaDB 10.3+ — только для живой проверки; тесты базу не трогают.

## Команды

```bash
npm install
npm run dev        # запуск из исходников (tsx watch)
npm test           # test:src (юнит-тесты) + test:dist (сборка и проверка dist/index.js по stdio)
npm run typecheck  # проверка типов src + тестов, без вывода файлов
npm run build      # очистить dist/ и собрать tsc
npm run smoke      # живая проверка только на чтение (нужны MYSQL_* в окружении)
```

`npm test` гоняет два набора. `test:src` выполняет все `src/**/*.test.ts` через `tsx`. `test:dist`
пересобирает `dist/` и запускает `test/dist-smoke.test.js`, который поднимает **собранный** сервер
как настоящий MCP-хост — по stdio — и проверяет набор инструментов, аннотации, схемы и поведение
без учётных данных. Оба набора работают офлайн: ни одного подключения к базе.

## Локальный запуск

```bash
npm run build
MYSQL_HOST=127.0.0.1 MYSQL_USER=root MYSQL_PASS=secret MYSQL_DB=test node dist/index.js
```

Сервер печатает в stderr строку вида
`mcp-mysql-client работает через stdio (root@127.0.0.1:3306/test, только чтение)` и ждёт MCP-хендшейк
на stdin. Без учётных данных он всё равно стартует — это часть контракта, см. ниже.

## Живая проверка

```bash
MYSQL_HOST=... MYSQL_USER=... MYSQL_PASS=... MYSQL_DB=... MYSQL_SSL=true npm run smoke
```

`smoke` только читает: версия сервера, размер базы, список таблиц, структура первой таблицы,
`SELECT 1`, `SHOW GRANTS`. Ни одной изменяющей операции — его безопасно запускать против боевой
базы, но лучше под пользователем с правами только на чтение.

## Что проверяют тесты

| Файл | О чём |
| --- | --- |
| `src/sql.test.ts` | Классификация SQL: строки и комментарии, `/*!`, CTE перед `DELETE`, `EXPLAIN ANALYZE`, `INTO OUTFILE`, несколько инструкций |
| `src/config.test.ts` | Разбор окружения, деградация вместо падения, TLS, пароль из файла, потолки |
| `src/client.test.ts` | Ошибка учётных данных вместо попытки подключения, нормализация бинарных значений |
| `src/tools/*.test.ts` | Поведение инструментов на фейковом клиенте: отказы до подключения, подтверждения, группировка индексов |
| `test/dist-smoke.test.js` | Собранный сервер: хендшейк, инвентарь инструментов, аннотации, деградация, отказы по политике |

## Контракт деградации

Сервер **никогда не завершается из-за конфигурации**. Нет учётных данных — стартует, отвечает на
`initialize` (с предупреждением в `instructions`) и на `tools/list`, а каждый вызов инструмента
возвращает ошибку, называющую недостающие переменные. Некорректное значение (`MYSQL_PORT=abc`,
нечитаемый `MYSQL_SSL_CA`) деградирует так же, но дополнительно сообщает, что именно сломано.

Причина простая: сервер, упавший до хендшейка, виден пользователю как красный крестик без причины.

## Стиль

- Комментарии в коде — по-английски, сообщения пользователю и модели — по-русски.
- zod остаётся на v3 (`^3.25.0`); схемы полей — фабрики, а не общие константы (иначе в JSON-схеме
  появляется `$ref`, который часть клиентов не разыменовывает).
- Новый инструмент нужно добавить в `EXPECTED` в `test/dist-smoke.test.js` и описать в
  `docs/TOOLS.md` — тест проверит, что он зарегистрирован и аннотирован.
